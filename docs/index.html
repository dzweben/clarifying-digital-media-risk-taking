The order things were run in, and why

The paper builds one argument, and each analysis exists because of what the one before it left open. Running them out of order still produces numbers, but the numbers stop answering the question they were meant to answer.

Paper Analysis The question it answers
3.2.1 Descriptives, Table 4 What do these measures look like in each cohort
3.2.2 Correlations, Table 5 Is SSMU related to risk taking and to the traits at all
3.2.3 Shapley, in text Of the things that are related, which carries the most weight
3.2.4 Indirect effects, Table S3 Do the traits reach SSMU through risk taking
3.2.5 Subtypes, then hierarchical regression, Table S4 Which kind of risk, and does any of it survive controlling for traits
3.2.6 Social vs parasocial, Table 6 Is this about screen time, or about the kind of platform

Read down that column and the argument narrows: does risk matter, how much, through what path, which kind, and on which platforms. Two orderings inside it are doing real work.

Shapley comes before the regression, not instead of it. The predictors are correlated, so betas depend on entry order. Shapley is order-free, which makes it the honest first look at relative contribution. The hierarchical regression then asks the stricter question — whether risk adds anything after traits have had first claim on the shared variance.

The subtype intercorrelations come before the subtype analyses. They establish that the three kinds of risk are related but not interchangeable (high- and low-stakes negative risk correlate at .55 and .42; low-stakes positive risk does not track high-stakes negative risk at all). Without that, splitting risk into three predictors in Step 4 would be unmotivated.

What changes on cohort 1. The order does not. What changes is that there is no YRBS substance scoring, so high-stakes negative risk drops out of Table 5, Table 6, Step 4 of Table S4, and the total risk variety composite. Set use_high_stakes <- FALSE in section 1 and everything downstream adjusts. Step 4 then tests two risk predictors rather than three, which is not comparable to the published ΔR², so report it on its own terms.

Scoring and cleaning are yours

This starts from an analysis-ready file: one row per participant, every scale already scored, outliers already handled. It does not score anything.

DEFT used a good many more scales than show up in these models, and they were all scored to the lab's standards. Rebuilding a couple of them inside an analysis script would only ever be a partial picture of that, so it is left out entirely. Score it the way the lab scores it.

Same for outlier handling. For reference, DEFT screened at |z| > 3 per variable and blanked the offending cell rather than dropping the row, so a participant with one implausible foraging value still contributed everywhere else. That removed about half a percent of cells. Use whatever your standard is.

If any of the scoring is unclear, ask me — happy to sit down and go through it rather than have it guessed at.

PNRT: important caveat

Scoring is yours, but the PNRT is worth writing down because we scored it differently than usual and the item lists are not recorded anywhere else.

Every PNRT activity is asked twice: have you ever done this, and if so, how often in the past six months. Variety is normally scored off the second question — an activity counts as 1 if there was any engagement in the past six months and 0 if there was none.

We could not do that. For the first six months of LITE — before Avi and I were on it — the frequency follow-up gave participants no way to answer zero times in the past six months once they had already said yes to ever having done the activity. So for those participants the frequency item cannot tell recent engagement apart from none.

We score variety off the ever items, and we have kept doing that since. The zero option may well have been fixed by now, but do not switch — the ever score is what DEFT uses, and cohort 1 needs to be scored the same way for the two to be comparable.

pnrt_personal counts as negative and pnrt_secret counts as positive, which is not what the names suggest.

Helpers.

zscore <- function(x) (x - mean(x, na.rm = TRUE)) / sd(x, na.rm = TRUE)

# Three star levels. Study 1 additionally marked p < .10; Study 2 does not.
format_r <- function(r, p) {
  stars <- if (is.na(p)) "" else if (p < .001) "***" else if (p < .01) "**" else if (p < .05) "*" else ""
  sprintf("%.2f%s", r, stars)
}

format_p_num <- function(p) if (p < .001) "< .001" else sprintf("%.3f", p)

The SSMU composite is built here, before anything is joined on. The three MTES subscales are on different scales — time is a sum across platforms, the other two are item means — so each is z-scored before averaging. Without that, time would dominate.

It has to happen at this point rather than later. z-scoring is relative to whoever is in the frame, so if a join has already changed the row count the mean and SD shift with it. Section 3 joins the YRBS file, and duplicate PIDs there will expand the data.

6. Correlations — Table 5

One published table, two panels, written as two files. Stack them to rebuild Table 5.

Correlations are pairwise complete, not listwise. Each cell uses everyone who has both variables, so N differs slightly across cells — which is why the table carries significance stars rather than a single N.

main_vars <- c("mtes_zscore", "impulsivity", "reward_sensitivity", "exploration")
row_vars  <- c(main_vars, "risk_variety", risk_subtypes)

get_r_p <- function(d, x, y) {
  d2 <- d[, c(x, y)]
  d2 <- d2[complete.cases(d2), ]
  if (nrow(d2) < 3) return(list(r = NA_real_, p = NA_real_))
  test <- cor.test(d2[[x]], d2[[y]], method = "pearson")
  list(r = unname(test$estimate), p = test$p.value)
}

build_corr_table <- function(d) {
  r_mat <- matrix(NA_real_, nrow = length(row_vars), ncol = length(main_vars),
                  dimnames = list(row_vars, main_vars))
  p_mat <- r_mat
  for (rv in row_vars) for (cv in main_vars) {
    if (rv == cv) next                      # diagonal stays blank, as in the paper
    res <- get_r_p(d, rv, cv)
    r_mat[rv, cv] <- res$r
    p_mat[rv, cv] <- res$p
  }
  formatted <- matrix("", nrow = nrow(r_mat), ncol = ncol(r_mat), dimnames = dimnames(r_mat))
  for (i in seq_len(nrow(r_mat))) for (j in seq_len(ncol(r_mat))) {
    if (!is.na(r_mat[i, j])) formatted[i, j] <- format_r(r_mat[i, j], p_mat[i, j])
  }
  list(formatted = as.data.frame(cbind(Variable = rownames(formatted), formatted)),
       numeric   = as.data.frame(cbind(Variable = rownames(r_mat), r_mat)))
}

7. Risk subtype intercorrelations

Not a table — these open section 3.2.5. They carry the argument that the subtypes are related but not interchangeable, which is what justifies analysing them separately in the next section rather than collapsing them.

run_corr <- function(d, x, y, cohort) {
  d2 <- d[, c(x, y)]
  d2 <- d2[complete.cases(d2), ]
  if (nrow(d2) < 3) return(data.frame(cohort = cohort, var1 = x, var2 = y, r = NA, p = NA, n = nrow(d2)))
  test <- cor.test(d2[[x]], d2[[y]], method = "pearson")
  data.frame(cohort = cohort, var1 = x, var2 = y,
             r = round(unname(test$estimate), 3),
             p = round(test$p.value, 4), n = nrow(d2))
}

8. Shapley value regression

The predictors are correlated, so ordinary betas depend on entry order and each predictor's apparent importance shifts with whatever else is in the model. Shapley averages each predictor's contribution to R² across every possible ordering, so the result sums to the model R² and does not depend on how the steps were ordered.

Read it as share of explained variance, not effect size. The adolescent model explains 20.8% of variance in MTES; risk variety accounts for about half of that 20.8%, not half of MTES.

This uses the composite rather than the three subtypes. Three heavily overlapping risk terms would split one construct's contribution across them and make every risk share look small. The na.omit is listwise by necessity — Shapley refits over every subset of predictors and needs one constant sample to compare them.

run_shapley <- function(data, cohort_label) {
  shap_df <- data %>%
    dplyr::select(mtes_zscore, risk_variety, reward_sensitivity,
                  impulsivity, exploration, gender) %>%
    na.omit()

  shap_values <- shapleyvalue(y = shap_df$mtes_zscore,
                              x = shap_df %>% dplyr::select(-mtes_zscore) %>% as.data.frame())

  # Row 1 = raw Shapley value; row 2 = proportion of model R2, as a percent.
  shap_out <- as.data.frame(shap_values)
  shap_out <- rbind(Shapley_Value = shap_out[1, ],
                    Percent_R2    = round(as.numeric(shap_out[2, ]) * 100, 2))

  write_csv(as.data.frame(shap_out),
            file.path(output_dir, paste0("study2_shapley_", cohort_label, ".csv")))
  shap_out
}

9. Indirect effects — Table S3

Cognitive trait → risk variety → SSMU, separately for each trait and each cohort. Six mediations, 5000 bootstrap resamples each. Slowest section here.

Risk taking is the mediator and social media engagement is the outcome. The data are cross-sectional, so this is statistical accounting, not causal sequence. The paper says "accounted for" throughout and never "led to" — keep that.

Predictors are standardized after subsetting to cohort and after na.omit, so everything is z-scored within the exact sample the models are fit on. Standardizing back in section 5 across both cohorts would put adolescents and young adults on a shared scale and change the coefficients. That is why risk_variety_raw is carried forward.

set.seed(2025)   # without this the bootstrap CIs move on every run

run_mediation_set <- function(data, cohort_label) {
  med_df <- data %>%
    dplyr::select(mtes_zscore, risk_variety_raw, reward_sensitivity, impulsivity, exploration) %>%
    mutate(risk_variety_z       = zscore(risk_variety_raw),
           reward_sensitivity_z = zscore(reward_sensitivity),
           impulsivity_z        = zscore(impulsivity),
           exploration_z        = zscore(exploration)) %>%
    na.omit()

  # Two models per mediation: predictor -> mediator, and predictor + mediator ->
  # outcome. Written longhand rather than looped -- mediate() re-evaluates the
  # model calls internally, and building the formulas programmatically breaks it.

  med_model_imp <- lm(risk_variety_z ~ impulsivity_z, data = med_df)
  out_model_imp <- lm(mtes_zscore ~ impulsivity_z + risk_variety_z, data = med_df)
  med_imp <- mediate(med_model_imp, out_model_imp, treat = "impulsivity_z",
                     mediator = "risk_variety_z", boot = TRUE, sims = 5000)

  med_model_rs <- lm(risk_variety_z ~ reward_sensitivity_z, data = med_df)
  out_model_rs <- lm(mtes_zscore ~ reward_sensitivity_z + risk_variety_z, data = med_df)
  med_rs <- mediate(med_model_rs, out_model_rs, treat = "reward_sensitivity_z",
                    mediator = "risk_variety_z", boot = TRUE, sims = 5000)

  med_model_exp <- lm(risk_variety_z ~ exploration_z, data = med_df)
  out_model_exp <- lm(mtes_zscore ~ exploration_z + risk_variety_z, data = med_df)
  med_exp <- mediate(med_model_exp, out_model_exp, treat = "exploration_z",
                     mediator = "risk_variety_z", boot = TRUE, sims = 5000)

  # d0 = indirect (ACME), z0 = direct (ADE), n0 = proportion mediated.
  extract_results <- function(m, predictor_name) {
    data.frame(
      Predictor = predictor_name,
      Indirect  = sprintf("%.2f (%.2f, %.2f), %.3f", m$d0, m$d0.ci[1], m$d0.ci[2], m$d0.p),
      Direct    = sprintf("%.2f (%.2f, %.2f), %.2f", m$z0, m$z0.ci[1], m$z0.ci[2], m$z0.p),
      Prop      = sprintf("%.1f%%, %.2f", m$n0 * 100, m$n0.p),
      stringsAsFactors = FALSE)
  }

  out <- bind_rows(extract_results(med_imp, "impulsivity"),
                   extract_results(med_rs,  "reward_sensitivity"),
                   extract_results(med_exp, "exploration"))

  write_csv(out, file.path(output_dir, paste0("study2_mediation_", cohort_label, ".csv")))
  out
}

10. Hierarchical regression — Table S4

Once you account for who someone is dispositionally, does what they do still explain anything about their social media engagement?

  1. sex + impulsivity
  2. + reward sensitivity
  3. + exploration
  4. + the risk subtypes

Sex is a covariate from Step 1, not a predictor of interest. Entering the cognitive traits before risk is the conservative ordering — it gives the dispositional account first claim on the shared variance, so whatever risk picks up in Step 4 is over and above traits. The ΔR² at Step 4 is the test.

Listwise deletion happens once, up front, so all four steps are fit on the same participants. Otherwise the ΔR² comparisons would be across different samples and anova() would be meaningless.

build_hier_table <- function(data, out_name) {
  model_vars <- c("mtes_zscore", "gender", "impulsivity", "reward_sensitivity",
                  "exploration", risk_entry_order)

  d <- data %>% dplyr::select(dplyr::all_of(model_vars)) %>% na.omit()

  base <- "mtes_zscore ~ gender + impulsivity"
  f <- c(base,
         paste(base, "+ reward_sensitivity"),
         paste(base, "+ reward_sensitivity + exploration"),
         paste(base, "+ reward_sensitivity + exploration +",
               paste(risk_entry_order, collapse = " + ")))

  models     <- lapply(f, function(x) lm(as.formula(x), data = d))
  models_std <- lapply(models, lm.beta)          # betas in the table are standardized
  anova_res  <- do.call(anova, models)           # step-to-step delta R2 tests

  format_beta <- function(beta, p) {
    stars <- if (p < .001) "***" else if (p < .01) "**" else if (p < .05) "*" else if (p < .10) "+" else ""
    sprintf("%.2f%s", beta, stars)
  }

  rows <- list()
  for (i in seq_along(models)) {
    summ <- summary(models[[i]]); summ_std <- summary(models_std[[i]])

    rows[[length(rows) + 1]] <- data.frame(Step = paste0("Step ", i), Predictor = "",
                                           Beta = "", SE = "", t = "", p = "", stringsAsFactors = FALSE)

    for (j in 2:nrow(summ$coefficients)) {       # start at 2 to skip the intercept
      rows[[length(rows) + 1]] <- data.frame(
        Step = "",
        Predictor = rownames(summ$coefficients)[j],
        Beta = format_beta(summ_std$coefficients[j, "Standardized"], summ$coefficients[j, "Pr(>|t|)"]),
        # SE and t come from the unstandardized fit; only beta is standardized.
        SE = sprintf("%.2f", summ$coefficients[j, "Std. Error"]),
        t  = sprintf("%.2f", summ$coefficients[j, "t value"]),
        p  = format_p_num(summ$coefficients[j, "Pr(>|t|)"]),
        stringsAsFactors = FALSE)
    }

    r2 <- summ$r.squared
    fstat <- summ$fstatistic
    fval <- fstat[1]; df1 <- fstat[2]; df2 <- fstat[3]
    pval <- pf(fval, df1, df2, lower.tail = FALSE)

    delta_r2 <- ""
    if (i > 1) {
      delta <- r2 - summary(models[[i - 1]])$r.squared
      delta_r2 <- paste0(", Delta R2 = ", sprintf("%.3f", delta),
                         ", p = ", format_p_num(anova_res$`Pr(>F)`[i]))
    }

    rows[[length(rows) + 1]] <- data.frame(
      Step = "",
      Predictor = paste0("R2 = ", sprintf("%.3f", r2),
                         ", F(", df1, ", ", df2, ") = ", sprintf("%.2f", fval),
                         ", p = ", format_p_num(pval), delta_r2),
      Beta = "", SE = "", t = "", p = "", stringsAsFactors = FALSE)
  }

  out <- bind_rows(rows)
  write_csv(out, file.path(output_dir, out_name))
  out
}

On structuring Step 4. All subtypes go in together. They correlate between .25 and .55, so each beta is that subtype's unique contribution net of the others, and none reaches significance in the young adult model even though the block as a whole sits near threshold. Two alternatives, both fine if stated: composite in Step 4 and subtypes in Step 5, which tests "does risk matter" before "which kind"; or three separate Step 4 models, one subtype each, which reads each subtype cleanly but runs three tests where the paper ran one. What is not fine is trying each and reporting whichever makes risk significant.

11. Social versus parasocial — Table 6

If the link between social media and risk were just screen time, it would not matter what kind of platform the time was spent on. It does — risk tracks reciprocal platforms and not one-sided ones, in both cohorts.

Steiger's z is the right test because the two correlations being compared share a variable (the risk subtype) and come from the same people. Comparing two r values directly would ignore that dependency and overstate the difference. The test needs a third correlation, social use with parasocial use, to know how dependent they are.

run_steiger <- function(data) {
  rows <- list()
  for (pred in risk_subtypes) {
    r_social            <- cor(data[[pred]],    data$social_use,     use = "pairwise.complete.obs")
    r_parasocial        <- cor(data[[pred]],    data$parasocial_use, use = "pairwise.complete.obs")
    r_social_parasocial <- cor(data$social_use, data$parasocial_use, use = "pairwise.complete.obs")
    n <- nrow(na.omit(data[, c(pred, "social_use", "parasocial_use")]))

    test <- cocor.dep.groups.overlap(r.jk = r_social,             # risk x social
                                     r.jh = r_parasocial,         # risk x parasocial
                                     r.kh = r_social_parasocial,  # social x parasocial
                                     n    = n)
    steiger <- test@steiger1980

    rows[[length(rows) + 1]] <- data.frame(
      Risk_Subtype = pred,
      r_social     = round(r_social, 2),
      r_parasocial = round(r_parasocial, 2),
      # Sign flipped so a negative z means social > parasocial, matching the
      # direction printed in Table 6. cocor orders the comparison the other way.
      steiger_z    = round(-1 * steiger$statistic, 2),
      p_value      = round(steiger$p.value, 3),
      n            = n)
  }
  bind_rows(rows)
}
